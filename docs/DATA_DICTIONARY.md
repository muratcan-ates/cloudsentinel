# Data Dictionary

*Every table, every field: what it means, what unit it carries, where it
comes from, and how long it lives. Written for the person who has to answer
"where does this number come from?" without reading the code — a reviewer, a
teammate on their first day, or us in six months.*

Companions: [`architecture.md`](architecture.md) for why the shape is what it
is, [`SLO.md`](SLO.md) for what we promise about serving it,
[`LIMITATIONS.md`](LIMITATIONS.md) for what it deliberately is not.

## Conventions that hold everywhere

| Convention | Rule |
|---|---|
| **Timestamps** | SQLite `TEXT`, UTC, `YYYY-MM-DD HH:MM:SS`, written by `datetime('now')` — never by the application clock, so one process's timezone cannot skew the record |
| **Dates** | `TEXT`, ISO-8601 `YYYY-MM-DD`. A *date* is a business day in the estate; a *timestamp* is when we learned about it |
| **Money** | `REAL`, the dataset's `currency` (bundled fixtures: USD), per day unless the field name says `monthly`. Every figure is computed in Python and never generated by a model |
| **`*_json` columns** | `TEXT` holding one JSON object. Denormalised on purpose: these are evidence payloads, read whole and never queried into |
| **Ids** | `INTEGER PRIMARY KEY` (SQLite rowid). Stable within a database file, meaningless across one — the deploy disk is ephemeral |
| **Booleans** | `INTEGER` 0/1; SQLite has no boolean type |
| **Retention** | Nothing is deleted in normal operation. `POST /ops/demo-reset` clears the decision state for a rehearsal and deliberately **spares** `ai_usage` and `llm_cache`, because quota history is real spend |

**Where the rows come from.** Three sources, and the distinction matters when
reading any figure: **fixture** (a bundled JSON file under `app/data/`),
**derived** (computed by the app from fixture or persisted data), and
**operator** (typed by a human). `/health`'s `data_sources` reports which lane
is which at runtime, and it reports what is actually being *served* — a lane
configured for a live feed that fell back answers `mock (feed unavailable)`
rather than repeating the config.

## Signal and decision chain

### `events` — one detected signal, deduplicated

The natural key `(kind, service, occurred_on)` is UNIQUE: rescanning the same
day never produces a second row, which is what makes the scan safe to run on
a cadence.

| Field | Type | Unit / domain | Source | Meaning |
|---|---|---|---|---|
| `id` | INTEGER | — | derived | Stable handle used by `/anomalies/{event_id}/…` |
| `kind` | TEXT | `cost_anomaly` · `security_anomaly` · `fraud_signal` | derived | Which lane detected it |
| `service` | TEXT | service name | fixture | The estate component, e.g. `compute`, `auth-gateway` |
| `occurred_on` | TEXT | ISO date | fixture | The business day the signal is *about* |
| `payload_json` | TEXT | JSON | derived | The detector's own output: cost, baseline, z-score, severity, detector id and its parameters |
| `analysis_json` | TEXT | JSON, nullable | derived | The Analyst's triage, once run. NULL until then |
| `evidence_snapshot_json` | TEXT | JSON, nullable | derived | The window of records frozen at analysis time, so a re-read reproduces the same reasoning even after the estate moves |
| `created_at` | TEXT | UTC timestamp | derived | When the scan persisted it |

### `actions` — one proposal awaiting a human

| Field | Type | Unit / domain | Source | Meaning |
|---|---|---|---|---|
| `id` | INTEGER | — | derived | Card id, the one an operator quotes |
| `event_id` | INTEGER | FK `events.id` | derived | The signal that caused it |
| `title` | TEXT | — | derived | One-line summary shown in the inbox |
| `detail_json` | TEXT | JSON | derived | The evidence pack: `category`, `preferred` stance, both `options`, `savings`, `confidence`, `transcript`, `trace`, `memory`, and after execution an `execution` block |
| `state` | TEXT | `proposed` · `approved` · `rejected` · `executed` | derived + operator | The lifecycle position. Only `approved` may be executed |
| `proposed_at` | TEXT | UTC timestamp | derived | Filing time; the TTL clock starts here and resets on reopen |
| `decided_at` | TEXT | UTC timestamp, nullable | operator | When a human ruled |
| `decided_by` | TEXT | username or agent id, nullable | operator | Who ruled. `agent:*` values mean a deterministic cross-lane filing, never an approval |
| `executed_at` | TEXT | UTC timestamp, nullable | derived | When the simulated execution ran |

**`detail_json.savings`** carries the money: `daily_excess` (currency/day
over baseline), `cautious_monthly` and `bold_monthly` (currency/month, the
two stances). `cautious_monthly` is the figure every roll-up uses — the
conservative one, on purpose.

### `action_events` — the append-only lifecycle trail

Never updated, never deleted. This is what makes a card's history a record
rather than a claim.

| Field | Type | Unit / domain | Source | Meaning |
|---|---|---|---|---|
| `id` | INTEGER | — | derived | — |
| `action_id` | INTEGER | FK `actions.id` | derived | The card |
| `transition` | TEXT | `filed` · `approved` · `rejected` · `executed` · `reopened` · `expired` · `suppressed` | derived + operator | What happened, constrained by CHECK |
| `actor` | TEXT | username or `agent:*`, nullable | operator/derived | Who did it |
| `note` | TEXT | free text, nullable | operator | The rationale, mandatory on `rejected` |
| `created_at` | TEXT | UTC timestamp | derived | When |

### `decisions` — the verdict ledger that feeds decision memory

Separate from `actions` because a verdict is a durable fact about the past,
while a card is a mutable object. `action_id` is nullable: seeded demo
verdicts and lane-level decisions have no card.

| Field | Type | Unit / domain | Source | Meaning |
|---|---|---|---|---|
| `id` | INTEGER | — | derived | — |
| `action_id` | INTEGER | FK `actions.id`, nullable | derived | The card ruled on, when there was one |
| `service` | TEXT | service name | derived | What the verdict was about — the key decision memory matches on |
| `verdict` | TEXT | `approved` · `rejected` | operator | The ruling, constrained by CHECK |
| `rationale` | TEXT | free text, nullable | operator | Why. Mandatory on rejection |
| `input_context_json` | TEXT | JSON | derived | What the operator was looking at, so a later reader can judge the verdict on its own evidence |
| `created_at` | TEXT | UTC timestamp | derived | When |

### `audit_ledger` — the tamper-evident seal

Hash-chained: each entry commits to the previous one, so a silently edited or
removed row breaks verification at `/audit/verify`. Created lazily on first
seal.

| Field | Type | Unit / domain | Source | Meaning |
|---|---|---|---|---|
| `stream` | TEXT | e.g. `decisions` | derived | Which record type this entry seals |
| `ref_id` | INTEGER | id in that stream | derived | The sealed row. `(stream, ref_id)` is UNIQUE |
| `body` | TEXT | canonical JSON | derived | Exactly the bytes that were hashed |
| `prev_hash` | TEXT | SHA-256 hex | derived | The chain link |
| `entry_hash` | TEXT | SHA-256 hex | derived | This entry's digest |
| `sealed_at` | TEXT | UTC timestamp | derived | When it was sealed |

## Operations and provenance

### `pulse_log` — one row per completed scan cycle

| Field | Type | Unit / domain | Source | Meaning |
|---|---|---|---|---|
| `report_json` | TEXT | JSON | derived | The whole `PulseReport`: signal counts per lane, proposals filed and reused, LLM budget and spend, the briefing, the chain trace |
| `created_at` | TEXT | UTC timestamp | derived | **Freshness lives here.** `/ops/health/watch` and `/ready` read the newest value to decide whether the standing watch has gone stale |

### `agent_feed` — inter-agent traffic, streamed to the dashboard

| Field | Type | Unit / domain | Source | Meaning |
|---|---|---|---|---|
| `agent` | TEXT | agent name or `operator` | derived | Who spoke |
| `kind` | TEXT | e.g. `signal`, `execute`, `review` | derived | Message class |
| `message` | TEXT | free text | derived | The human-readable line |
| `payload_json` | TEXT | JSON, nullable | derived | Structured detail behind it |

### `ai_usage` — the self-FinOps ledger

Never cleared, including by the demo reset: quota spent is spent, and a panel
that reads real accumulated numbers is the point.

| Field | Type | Unit / domain | Source | Meaning |
|---|---|---|---|---|
| `agent` | TEXT | analyst · recommender · skeptic · chronicler | derived | Which agent called |
| `model` | TEXT | model id | derived | What answered |
| `source` | TEXT | `gemini` · `fake` · `fallback` | derived | Which lane served it — `fallback` means the rules answered, not a model |
| `prompt_sha256` | TEXT | SHA-256 hex | derived | Prompt digest. The prompt itself is never stored |
| `from_cache` | INTEGER | 0/1 | derived | Whether a cache hit avoided the call |

### `llm_cache` — response reuse, keyed by content

`key` is SHA-256 over model + system instruction + prompt, so a changed
detector configuration correctly re-keys the cache: a different detector asks
a different question about the same numbers. Pruned to a row cap, oldest first.

### `idempotency` — replay protection for decision writes

`key` is the caller's `Idempotency-Key` scoped to the action and verb.
`response_json` holds the canonical answer, so a retry returns the original
result rather than doing the work twice.

### `telemetry_usage` — the app's own request counts

`(service, day)` composite key; `hits` is a counter. This is what the cost
lane serves under `SENTINEL_COSTS_SOURCE=self` — the app watching its own
traffic instead of a fixture.

### `routines`, `users`, `sessions`

`routines` stores saved multi-step operations (`steps_json`). `users` holds
local identity: PBKDF2 `password_hash` with a per-user `salt`, and one of four
`role` values (`viewer` · `analyst` · `approver` · `admin`). `sessions` maps
an opaque bearer `token` to a user; tokens expire by age at read time.

> **Not stored anywhere:** API keys, raw prompts, feed URLs with embedded
> tokens (dispatch records the target *host* only), or passwords in any
> recoverable form.

## Bundled datasets (`app/data/`)

| File | Shape | Meaning |
|---|---|---|
| `mock_costs.json` | `daily_costs[]` of `{date, service, cost}` + `currency`, `period` | The default estate: 4 services × 14 days, with two planted spikes and one borderline blip below the default threshold |
| `seasonal_costs.json` | same contract, 3 services × 70 days | Ten weeks with a deliberate weekly rhythm. Exists so the day-of-week baseline can be exercised at all — see [`the generator`](../scripts/make_seasonal_fixture.py) |
| `mock_security_events.json` | `daily_counts[]` of `{service, date, count}` | Event counts per service per day; `count` is a count, not money |
| `mock_fraud_events.json` | `events[]` of `{id, date, service, amount, typical_amount, account_age_days, country, home_country, tx_last_10m}` | Transaction-level features for the published rule score. `amount` and `typical_amount` are currency; `tx_last_10m` is a velocity count |
| `market_watch.json` | `opportunities[]` | A reviewed catalogue of savings patterns with `reduction_min`/`reduction_max` as fractions, plus `checked` dates — claims with a provenance stamp |

An external feed must answer the exact same contract as the file it replaces.
Records that do not fit are dropped and counted rather than admitted: one
`NaN` in one row would poison every mean and z-score computed after it.

## Derived figures worth naming

| Figure | Where | How it is computed |
|---|---|---|
| `z_score` | `events.payload_json`, `/anomalies` | `(cost − baseline centre) / baseline spread`, rounded to 2dp **before** the threshold comparison, so a reader recomputing from the payload always agrees with the stored severity |
| `service_mean` | `/anomalies` | The baseline centre the record was scored against — the weekday bucket's mean under seasonality, the window's otherwise |
| `severity` | `/anomalies` | `critical` above the critical-z line, `warning` above the threshold |
| `cautious_monthly` | `detail_json.savings` | Daily excess over baseline × 30, conservative stance. Python arithmetic; the model never produces a number |
| `approval_rate` | `/analytics/decisions`, `/runbooks/effectiveness` | `approved / (approved + rejected)` over persisted verdicts |
| `expires_in_hours` | `/actions` | TTL minus age. May read slightly negative between crossing the line and the sweep that expires the card — honest rather than clamped |
| `last_pulse_age_seconds` | `/ops/health/watch` | Now minus the newest `pulse_log.created_at`. Compared against 2× the configured watch interval to decide staleness |
