the thesis

one line, and then everything that had to be true for the line to be honest

◎

The machine watches. The human decides.

CloudSentinel is an agentic decision-support system for cloud operations. It detects anomalies in cost and security data, has AI agents reason about each signal and propose evidence-backed remediation options, and leaves every critical decision to a human operator. Detection is deterministic Python. The agents interpret and narrate; they never invent a number. Nothing executes without an approval, and the execution itself is simulated by design.

FastAPI and Python 3.12, sqlite3 in WAL mode as the store, a vanilla-JS dashboard under a strict content-security policy, and a Gemini provider behind an abstraction with a deterministic fake provider so the whole demo runs offline. 1270 pytest cases, ruff clean, no agent framework and no runtime dependency the dashboard has to fetch from anyone else.

What it is not

Each row is a decision that was made and written down, not a task nobody got to.

  • Not a cloud connector. No provider SDK, no credential, anywhere. The detection line is source-agnostic; the data is synthetic. by design
  • Not an actuator. Approving an action never changes any infrastructure. The mutation is simulated; only the record and an optional webhook delivery are real. by design
  • Not machine learning. Detection is a rolling-baseline z-score. Fraud is four published rules. Nothing is trained; nothing is learned beyond the arithmetic. by design
  • Not a system of record. SQLite on an ephemeral disk. The hash chain proves the history was not rewritten; it does not make the history survive a restart. known limit
  • Not multi-tenant, not SSO. One deployment serves one estate. Identity is local PBKDF2 accounts with four roles — no OIDC, no MFA, no recovery. known limit
I

the five beats

the product read left to right — a signal enters at the top row and leaves as a measured outcome at the bottom

  • 1 · Detect. A deterministic detector scores three lanes against a rolling baseline: cloud cost, security event counts, and payment events (the last by published rule score, not statistics). app/detection.py
  • 2 · Reason. The Analyst triages each cost anomaly with cited evidence. The Recommender proposes one cautious and one bold option with risk and rollback. A Skeptic reviews contested calls. A Chronicler narrates the run. Every money figure is computed in Python. app/analyst.py
  • 3 · Decide. Proposals wait in a decision inbox. An operator approves or rejects with a recorded rationale. Nothing executes unapproved, and execution stays simulated. app/actions.py
  • 4 · Remember. Verdicts become decision memory that future recommendations consume — and disclose, on the card, as a count of how many were considered. A hop-by-hop trace shows how the chain actually ran. app/decisions.py
  • 5 · Account. Analytics turn the persisted history into a HITL funnel, approved savings, trend, forecast, what-if and ROI figures — plus a self-FinOps view of the system's own model usage. app/analytics.py

One call runs all five

POST /pulse

The pulse resolves the active mission, runs the scan, triages every cost anomaly, escalates the contested ones to debate, files proposals into the inbox, and asks the Chronicler for a briefing — under a per-run call budget of 14 model calls by default. Exhausting the budget degrades every agent to its rule-based fallback, labelled as such on the card. The last run survives a reload at GET /pulse/last.

the rooms

the dashboard is one page with six rooms; each room is a real URL, so back, forward and sharing all work

Six rooms, in reading order

  • Watch Signals surface. The desk (what the estate is holding right now), the anomaly feed with the live sentinel radar, and the cost ledger with share-of-spend. /watch
  • Investigation Evidence and triage. One open signal at a time: the cited evidence rows, the Analyst's classification and confidence, the sparkline of that service's own history. /investigate
  • Decision desk The hand decides. The decision inbox with both options, risk, rollback and computed savings, plus the append-only decision ledger underneath it. /decide
  • Intelligence Results measured. The HITL funnel, approved savings, trend and month-end forecast, what-if and ROI, the AI-usage ledger — and market watch, the standing moves worth doing anyway. /intel
  • Brain Memory and reflection. Observations, projections and improvement recommendations from persisted history; the self-review cycle; saved routines; the runbook library; the detector backtest; operator sign-in. /brain
  • Broadsheet The story told. Every panel on one scrolling page — the view the printed shift handover is taken from. /broadsheet

The nine panels behind the six rooms

A room is a selection of panels. These are the panels, in the order the broadsheet prints them.

III

the agents

six members, and the guardrails are part of the definition — the roster below is the one GET /agents returns, read out of the code

  • Reflex Deterministic first responder. Resolves the mission's detection settings, runs the scan and reports its own measured latency. May not call a model at all. Fires on every scan and every pulse. pure Python
  • Analyst Triage. Classifies each cost anomaly REAL / SEASONAL / DATA_ERROR / KNOWN_CHANGE with cited evidence rows and a self-assessed confidence. Its citations are validated against the real evidence window; a critical signal gets a second self-review pass. Answers are cached; fallbacks never are. model or fallback
  • Recommender Remediation. Drafts exactly one cautious and one bold option, each with risk and a rollback plan, and consumes decision memory while disclosing how much it considered. Savings are computed in Python and its narrative is post-checked to within ±5% of them. One open card per signal. model or fallback
  • Skeptic Adversarial review. Challenges a contested draft and may overturn the stance, on the record. At most one call per decision, and the transcript is persisted with the proposal. model or fake
  • Chronicler Narration. Turns the run's computed facts into an operator briefing — headline, summary, watch-next. Never invents a figure, is charged against the pulse budget, and is cached by the exact facts it was given. model or fallback
  • Operator The human. Approves, rejects and (simulated) executes; every verdict feeds decision memory. Nothing executes unapproved, decisions are idempotent, and a rejection must carry a rationale. human in the loop

The debate ladder

escalation

A confident, uncontested warning goes straight to the inbox. A contested warning — low recommender confidence, an analyst/recommender disagreement, a service that has tripped the reflex on three anomaly days inside two weeks, or a BOLD answer under the stakes-raised bar — earns one Skeptic review. A contested critical signal convenes a three-seat review panel: three Gemini variants when a live key is configured, three deterministic personas (stability, throughput, evidence) offline. The majority over answered seats decides the stance; dissent and abstentions stay in the transcript, a dead seat abstains, and a below-quorum panel keeps the draft rather than inventing a verdict.

What no agent is allowed to do

  • Produce a number the operator acts on. Savings, costs, z-scores and fraud points are Python arithmetic. Money-looking figures in agent prose are post-checked ±5% against the computed value and flagged on the card when they cannot be verified.never
  • Touch a security or fraud signal. Those lanes are operator-facing facts. The agent endpoints answer 409 on a foreign event kind, and the HITL funnel counts cost anomalies only.never
  • Take instructions from the data. Every untrusted payload enters a prompt between delimiters, as data. Model-cited evidence ids are checked against the real evidence window before they are shown.never
  • Execute anything. Only the operator can move a card out of proposed, and the execute transition mutates no infrastructure.never
  • Fail the run. A dead provider, an exhausted budget or a transport timeout degrades an agent to its rule-based fallback, tagged source: fallback. The card is still filed.never
IV

the maths

how a number becomes a signal — all of it in app/detection.py, none of it trained

The window

Statistics come from a true calendar window: the last 28 days ending at the dataset's newest date, not from a service's whole history. A months-old regime cannot poison today's baseline, and a service whose data stopped before the window ages out instead of being scored against fossils. A service needs at least 7 records inside the window to be scored at all; below that it is reported in insufficient_data_services rather than guessed at. A record whose cost is missing, non-numeric or non-finite is dropped before any statistic runs, and the drop is counted — never silently treated as zero.

The score

For each service the detector computes a centre and a spread over the window, then scores every record as (cost − centre) ÷ spread. A record is flagged when the absolute value of that score meets the mission's threshold (2.0 by default), and it is critical at 3.0 or above, a warning otherwise. A perfectly flat window has zero spread and produces no score — there is nothing to be unusual against.

Two ways to be "normal"

  • zscore Mean and population standard deviation. The default. Simple and familiar — and one big spike inflates both, hiding the next one.default
  • mad Median plus median-absolute-deviation scaled by 1.4826, chosen with SENTINEL_DETECTOR=mad. A single extreme value cannot move it. If more than half the window is identical the MAD collapses to zero, so it falls back to the classic z-score rather than hiding every spike.opt-in

Three switches, all off by default

env
  • Weekly seasonality Compares Mondays with Mondays. It engages only when every weekday bucket holds at least 3 records and is large enough for the requested threshold to be mathematically reachable — otherwise it keeps the flat baseline instead of silently muting the lane. Switch: SENTINEL_SEASONAL.off
  • Leave-one-out Scores each record against a baseline that excludes that record, so an outlier cannot inflate the centre and spread it is then measured against. Switch: SENTINEL_LEAVE_ONE_OUT.off
  • Baseline window The 28-day default is tunable through SENTINEL_BASELINE_WINDOW_DAYS, with a floor at the 7-record minimum and a ceiling at a year — a "rolling" baseline longer than that is not rolling.28 days

Every flagged anomaly records which detector and which parameters produced it, so "why was this flagged" has a durable answer in the event payload.

The fraud lane does none of that

rule score

Four published rules, summed and clamped to 100, with every hit returned as rule / points / detail so any score can be recomputed by hand.

  • Amount vs the account's typical ratio ≥ 10, ≥ 3, ≥ 1.5+40 / +25 / +10
  • Velocity ≥ 5 transactions in 10 minutes, ≥ 3+25 / +15
  • Geography transaction country differs from the home country+20
  • Account age younger than the configured cutoff (30 days)+15
  • Bands 70 and above suggests a hold, 40 and above asks for review, below that is clearmission config

It suggests a hold. It never blocks a payment, and no model is involved.

V

the missions

one engine, three YAMLs — a mission is the declarative description of one watch

What a mission file says

Missions live in configs/<name>.yaml, are parsed as data with a safe loader and validated hard by Pydantic before anything runs. Each file declares its own name, an organizational intent, a per-role intent, a detection block (source, threshold, critical z, detector, baseline window, seasonality) and an escalation block (the confidence bar below which debate fires).

Precedence everywhere: explicit argument > environment variable > mission YAML > code default.

How the three differ

The numbers are deliberately identical today — threshold 2.0, critical 3.0, z-score, 28-day window, seasonality off, debate bar 0.6 in all three. What differs is the source, the intent the agents inherit, and how much of the file is actually live.

  • finops Source: cost. The only mission whose signals reach the agent chain — analyst triage, recommender options, debate, decision inbox. Its role intents name the analyst, the recommender and the operator. full chain
  • security Source: security event counts per source. Identical detection line, own event kind, no LLM agent — signals are operator-facing facts. The escalation block is kept for schema uniformity and does not fire. detection only
  • fraud Source: payment events. Its detection block is schema-mandated but inert — no statistical pass runs. Only its extra rules block (band thresholds and the new-account cutoff) is live configuration. rules only

The loader refuses rather than guesses

An unknown key is a knob that does nothing. A duplicate key is silently won by the last one. A lax coercion ("2.0" for a number) hides a template that never got substituted. A value the detector would quietly override means the number in the file never runs. A shadowing file is the one you edit without it ever being the one that loads. All of them refuse to load, and the message names the file, the key and the range that would have been accepted. Mission names are allow-listed to a strict slug, so a path traversal can never reach outside configs/.

Switching live

on stage

The dashboard's mission dropdown flips the active mission through POST /pulse?mission= as an in-memory override. Thresholds, detector and the debate bar re-read from another YAML, and every mission-following surface flips with them.

VI

the decision lifecycle

human-in-the-loop is a state machine, not a checkbox — every transition is persisted with a timestamp and an actor

The states

state machine

proposed → approved | rejected → executed (simulated), plus rejected → proposed when the hand reconsiders.

  • proposed The Recommender filed a card with both options, the evidence pack, the trace and the memory it consulted. This is the only decidable state.agent
  • approved A human said yes. The verdict, the rationale and the input context are written to decision memory.operator
  • rejected A human said no — and had to say why. A rejection without a non-empty rationale is refused with 422, because a terminal "no" is the memory a future recommendation will read.operator
  • reopened A rejected (or expired) card can return to proposed with a fresh TTL. The hand is allowed to reconsider; the trail keeps both moves.operator
  • executed Only reachable from approved, enforced by a database constraint. Writes a SIMULATION marker; may really deliver the incident report to a configured webhook after the transaction commits.operator
  • expired A proposal older than 72 hours is rejected on the next read and attributed to system:timeout. Expiry happens on request, not on a clock — the deploy target sleeps between requests and no scheduler could run there.system

The rules around the states

  • Idempotent decisions. An Idempotency-Key is claimed inside the same write transaction as the state change, so a double-clicked approve replays the first response instead of executing twice. Keys are scoped to action id plus verb, so one client key can never replay a foreign answer. Only successful decisions are stored for replay.100%
  • Alert suppression. While a card is still undecided, a later signal for the same service on the same lane folds into it as a counted repeat instead of opening a second card — 24 hours by default. The moment a human decides, the conversation is closed and the next signal earns its own card. Suppression never crosses lanes.24 h
  • Server-derived identity. A signed-in operator's identity is taken from the session, not from the request body, so the audit trail is not free browser text. With the approver gate on, the three decision verbs demand an approver or admin session while reads stay public.auth
  • A sealed trail. Every decision and lifecycle transition is sealed with the hash of the one before it. GET /audit/verify walks the chain and names the first broken link. It proves the history was not rewritten; it does not make the history survive a restart./audit/verify
  • Decision memory. Verdicts feed the Recommender's frozen memory prompt slot, and how many were considered is shown on the card. Nothing is learned silently./decisions
VII

real vs simulated

the one table a juror should read before believing anything else on the page

  • The cost, security and payment data Bundled fixtures by default. No real cloud bill has ever passed through this system.synthetic
  • The infrastructure change Executing an approved action writes a SIMULATION marker. Nothing in any cloud is touched, ever.simulated
  • The live tape A bounded random walk seeded from the fixture's real history. Labelled SIMULATED LIVE on the badge and pinned simulated: true in its payload — deliberately never the plain "live data" wording.simulated
  • The model on the public demo The deterministic fake provider. Confidence reads a fixed 0.50 there — that is the fake speaking, not a measured belief, and because 0.50 sits under the debate bar the escalation ladder runs on essentially every card.fake provider
  • The detection arithmetic Real code over whatever data is served, with the detector and its parameters recorded on every flag.real
  • The decision record Real: the verdict, the rationale, the operator identity behind it, and the append-only hash-sealed trail.real
  • The outbound dispatch Real: with a webhook configured, the incident report genuinely leaves the building after the execute commits, and the delivery outcome lands in the audit detail. A failed delivery never fails the execute.real
  • The live data paths Wired end to end and env-gated: external JSON feeds, an imported billing CSV, or the app's own request telemetry as the cost dataset. Real code — but never exercised against a production estate.opt-in
  • The savings figures Scenario estimates: the anomaly's daily excess projected over 30 days with a capture factor of 0.35 cautious, 0.70 bold. The assumption travels with the number on every surface that shows it. Computed, never generated — and not finance-grade.estimate

If something in the demo looks like it does more than this admits, this is the one to believe. The long version is docs/LIMITATIONS.md.

VIII

the boundaries

where the build stops on purpose, and what stops it

Around the model

  • Call budget A per-pulse cap (14 by default, overridable per run). Exhaustion degrades every agent to a labelled fallback — never a failure.14 / pulse
  • Hard timeout Every transport call is bounded at 30 seconds, so a hung request fails into retry and fallback instead of wedging a worker.30 s
  • Model allowlist A model must be on a short allowlist before it may serve live traffic. Membership means one thing: the free tier grants it non-zero quota, measured against a real key. A typo 404s into a silent abstention; a plausible name buys a panel seat that can never answer.4 models
  • Prompt spotlighting Untrusted payloads enter prompts between delimiters, as data and never as instructions.always
  • Quota discipline Answers are cached by exact request; fallbacks are never cached; every call — live, fake, cached or fallback — lands in a usage ledger the analytics account for. The project runs zero-cost by construction./analytics/ai

Around the process

  • Strict CSP Scripts are locked to 'self' on every path. Fonts are self-hosted and Swagger is vendored, so no external host is allowed anywhere — the API browser runs under the same policy as the dashboard.every path
  • Outbound guard Feed and webhook URLs are checked before the socket opens: https only, no loopback, link-local, private or reserved destination, and no redirect-following into one. A guard against being aimed inward.app/netguard.py
  • Boot-time posture audit Read-only mode, the approver requirement, the provider choice and the outbound escape hatch are all environment variables defaulting to off. Under a production profile a demo posture refuses to boot; every other profile logs its findings.on startup
  • Failure envelope A contended database answers 503 with a Retry-After; anything unhandled answers a JSON 500. A traceback goes to the log and never to the wire. The pulse endpoint is rate-limited.JSON, always
  • Two honest postures Showcase mode refuses every write, including login, and the UI disables the verbs it cannot honour rather than offering buttons that 403. Live-ops mode gates the three decision verbs behind an approver session while reads stay public and self-registration stays viewer-only.pick one
  • It scans itself bandit over the source and pip-audit over the shipped dependencies both gate CI, alongside ruff and the full suite on every push and pull request.make audit

Named non-goals

Real cloud provider adapters, PostgreSQL and migrations, background schedulers, bundled chat-platform integrations, and ML-based fraud models. Each is a deliberate boundary of this build rather than an oversight; none is required to demonstrate the thesis. There has been no load test and no external penetration test, and the agent-chain evaluation is a 200-case golden set of the team's own making — honest about its false positives, and not an independent benchmark.

run it

two commands to a running product — pip and venv, no other toolchain

The commands

  • make setup Creates the virtualenv and installs the runtime and dev requirements. Once per clone.first
  • make demo The demo stage: fake provider (no quota, no key), fixture dates rebased to this week, demo reset armed, simulated tape on. Serves on port 8000.then
  • make smoke From another shell: a PASS/FAIL sweep over the live chain, asserting on the answers and not just the status codes.verify
  • make test ruff, then the full suite on the fake provider — 1270 cases, deterministic and quota-free.gate
  • make run Plain local run without the demo staging. Or by hand: .venv/bin/uvicorn main:app --reload.plain
  • make drill The failure drill: proves the zero-budget fallback path and the rate limit.optional

Then open the dashboard, or drive the whole chain with one call and watch the tagged log stream: curl -X POST localhost:8000/pulse. Docker works too — the image is non-root with a stdlib healthcheck. On Windows, replace .venv/bin/ with .venv\Scripts\.
